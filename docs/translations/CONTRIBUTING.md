# 参与 pi 贡献

本指南的目的就是为双方节省时间。

## 理念

开宗明义：**pi 的核心是极简的**。

如果你的功能不属于核心，就应该做成 extension。会让核心膨胀的 PR 很可能被拒绝。

Pi 的核心存在的意义就在于极简、可扩展，从而能被 extension 影响和操纵。不过，即便是为 extension 提供的 hook 点，也需要经过充分的考量和讨论，避免引入无法维护的膨胀和复杂的交互。

## 唯一的规则

**你必须理解你自己的代码。** 如果你说不清楚你的改动做了什么、如何与系统其他部分交互，你的 PR 会被关闭。

用 AI 写代码没问题。提交自己都看不明白的 AI 生成垃圾则不行。

如果你使用 agent，请从 `pi` 根目录启动它，这样它会自动读取 `AGENTS.md`。你的 agent 必须遵守该文件中的规则和准则。

## 贡献门槛

新贡献者提交的所有 issue 和 PR 默认会被自动关闭。

周五到周日提交的 issue 不保证会被审查。如果有紧急事项，请到 Discord 上问：https://discord.com/invite/3cU7Bz4UPx

维护者每天都会审查被自动关闭的 issue，并重新打开其中有价值的。达不到下面质量标准的 issue 不会被重新打开，也不会收到回复。

认可通过维护者在 issue 下的回复来进行：

- `lgtmi`：你今后的 issue 不会再被自动关闭
- `lgtm`：你今后的 issue 和 PR 都不会再被自动关闭

该指令必须位于回复的开头（可以在一个或多个 `@username` 提及之后）或结尾。`lgtmi` 不授予提交 PR 的权利，只有 `lgtm` 才授予提交 PR 的权利。

## Issue 质量标准

提 issue 时，必须使用两个 GitHub issue 模板之一。

提 issue 时，保持简短、具体、值得一读。

- 保持简洁。如果一屏放不下，就是太长了。
- 用你自己的语气写（不要用 LLM 生成文本；实在要用，请追加一条明确标注为 AI 生成的评论）。
- 清楚地陈述 bug 或需求。
- 说明它为什么重要。
- 如果你想自己实现这个改动，请说明。

如果 issue 真实且写得不错，维护者可能会重新打开它，或按前述指令位置回复 `lgtmi` 或 `lgtm`。

## 封禁

如果你两次无视本文件，或者用 agent 生成的 issue 刷 issue 列表，你的 GitHub 账号将被永久封禁。

如果你通过自动化手段批量提交 issue，你的 GitHub 账号将被永久封禁。没有讨价还价的余地。

## 提交 PR 之前

除非已经有维护者按前述指令位置回复 `lgtm` 批准了你，否则不要开 PR。

提交 PR 之前：

```bash
npm run check
./test.sh
```

两者都必须通过。

不要编辑 `CHANGELOG.md`。changelog 条目由维护者添加。

如果你要给 `packages/ai` 添加新 provider，需要哪些测试见 `AGENTS.md`。

## 常见问题

### 为什么新 issue 和 PR 会被自动关闭？

pi 收到的 issue 数量超出了维护者能够负责任地实时审查的范围。许多报告达不到本指南的质量标准，或不符合 CONTRIBUTING.md 的要求。有些报告是提交者通过 agent 不加思考地扔进仓库的，而不是经过本人审查和打磨。自动关闭机制形成了一个缓冲区，让维护者可以按自己的节奏审查 issue 列表，并重新打开达到质量标准的 issue。

### 为什么周末的 issue 优先级更低？

我们在工作时间对 issue 列表做分类处理，因此周末会积压更多 issue。周五到周日提交的内容可能被漏掉，或在周一的审查队列中拿到较低的优先级。如果问题紧急，请到 Discord 上问，并附上简短描述、复现步骤（repro）和相关日志。

### 为什么有些 issue 没有回复？

回复也是维护工作的一部分。低信息量的 issue、表述不清的报告、重复 issue，以及不符合本指南的 issue 可能不经讨论就被关闭。这样能把时间留给可复现的 bug、经过认真思考的需求，以及那些做了功课、让报告可以直接行动的贡献者。

### 为什么不让 AI 处理所有分类工作？

AI 可以帮助归组重复项、总结报告、发现缺失的信息，但我们不信任它替维护者做最终决定。包装精美的 AI 生成 issue 仍可能是错误的、有误导性的，或者调查起来代价很高。人工审查始终是最后一道关卡。

### 这对贡献者不友好吗？

不是。这是防止维护者倦怠和 issue 列表被灌水的护栏。简短、具体、可复现的 issue 欢迎之至；用心打磨的贡献欢迎之至；自动化的垃圾、理所当然的态度，以及大量低成本刷出来的报告则不受欢迎。
