## 0. 文件定位：它在项目里是什么

`models.ts` 是 pi-ai 的**运行时中枢**。README 快速开始里的 `const models = builtinModels()` 拿到的对象就是这里 `ModelsImpl` 的实例。它只做三件事：

1. **Provider 注册表与模型目录管理**——40 家厂商注册进来，静态目录直接给，动态目录（如 OpenRouter 全量模型列表）可 refresh；
2. **每次调用前的认证解析**——`applyAuth` 把「存储的凭据 + 环境变量 + 请求时显式传的值」合并成最终请求配置；
3. **调用分发**——按 `model.provider` 找到厂商，再按 `model.api` 找到协议实现，把请求交给它。

**调用一条龙**（对照第 ⑥ 站）：

```
models.streamSimple(model, ctx, opts)
  → lazyStream 同步返回空流（你已学过的模式）
  → 背后: requireProvider 查厂商 → applyAuth 解析认证
  → provider.streamSimple(...)（createProvider 造的对象）
  → dispatch 按 model.api 路由到 src/api/*.ts 的协议实现
```

## 1. 预备概念（通用概念，先看这节）

**Provider / Model / API 协议的关系**：Model（一个模型条目）自带 `provider`（属于哪家）和 `api`（说哪种协议）两个外键；Provider（厂商）= 身份 + 认证方式 + 模型列表 + 绑定的协议实现。同一个 Provider 的不同模型可以说不同协议（所以 ⑩ 的 dispatch 按 `model.api` 而不是按厂商路由）。

**静态目录 vs 动态目录**：静态（Anthropic/OpenAI 内置目录，打包时定死）；动态（OpenRouter 等，运行时联网拉）。动态刷新是**两阶段**：先把上次缓存恢复出来（离线也能用），再联网拉新的。

**依赖注入（构造器注入）**：`ModelsImpl` 构造器接收三个接口参数——`CredentialStore`（凭据存哪）、`ModelsStore`（目录缓存存哪）、`AuthContext`（怎么读环境变量）。默认给内存实现；coding-agent 会换成落盘 `auth.json` 的实现。这就是 Spring 风格的构造器注入 / Go 里"收接口参数"，只是这里是构造器 + 默认值。

**generation（代数）防竞态**：动态目录刷新途中，provider 可能被替换或再次刷新。每次刷新把代数 +1，旧刷新的发布动作发现代数对不上就自我丢弃——防止旧数据覆盖新数据。类比：乐观锁版本号 + 取消信号。

**OAuth 刷新在锁内**：token 过期时的 refresh 走 `credentials.modify`（凭据存储的唯一写路径，串行化），两个并发请求同时发现过期也只会刷新一次——这是之前 `ApiKeyAuth` 笔记里"modify 是唯一写路径"设计的原因。

## 2. 逐站解析

### ① `Provider` 接口（:97-149）

原文注释（中译）：

> Provider 是具体的运行时单元。它持有 id/name/base 元数据、认证方法、模型列表和流式调用行为。
> `TApi` 让具体的 provider 工厂声明自己的模型用哪些 API（例如 `openaiProvider(): Provider<"openai-responses" | "openai-completions">`），让直接使用工厂的人拿到带类型的模型列表。在 `Models` 集合内部，provider 统一以 `Provider<Api>` 持有。

成员速览（`?` = 可选）：

| 成员 | 含义 |
|---|---|
| `id` / `name` / `baseUrl?` / `headers?` | 身份与默认地址/头 |
| `auth: ProviderAuth` | **必填**。注释强调：即使纯环境凭据（env var、AWS profile、ADC 文件）或免密本地服务器，也要提供 `apiKey` 认证——它的 `resolve()` 负责回答"配好了没" |
| `getModels(): readonly Model<TApi>[]` | 同步返回当前已知模型。注释：**不许 throw**，抛错的 provider 视为没有模型 |
| `refreshModels?(context)` | 仅动态 provider：先恢复 `context.stored` 缓存，再视情况联网；结果通过 `context.publish()` 发布 |
| `filterModels?` | 按凭据过滤可见模型（如订阅档位决定能用哪些） |
| `stream` / `streamSimple` | 两条调用通道；`fetchDeferred?` / `cancelDeferred?` 可选的延迟响应支持 |

**语法点**：`<TApi extends Api = Api>`——泛型约束（"必须是 Api 的子类型"）+ 默认值（不传就当任意 Api）。`readonly Model<TApi>[]`——只读数组，拿到方不能 push/改元素（防外部污染目录，≈ Go 里只给读方法不给 slice 引用）。

### ② `Models` 接口（:156-228）

原文注释（中译）：

> Provider 的运行时集合，附加认证应用与流式调用便捷方法。Provider 自己拥有流式行为；`Models` 负责解析认证，并把每个请求委托给拥有该模型的 provider。

这就是"门面"（Facade）：对外的一整套能力声明。按功能分四组读：

| 分组 | 方法 |
|---|---|
| 查询 | `getProviders` / `getProvider` / `getModels`（一家或全部）/ `getModel`（按 provider+id 查） |
| 目录刷新 | `refresh`（并发刷新选中的动态 provider；错误和取消装进结果返回，**不 reject**） |
| 认证 | `checkAuth`（探测"配好没"，不刷新 OAuth）/ `getAvailable`（返回认证完备的模型）/ `getAuth`（完整解析，见下）/ `login` / `logout` |
| 调用 | `stream` / `complete` / `streamSimple` / `completeSimple` + deferred 三件套 |

`getAuth` 注释值得读（中译要点）：按 provider id 解析，或传入 model 时附加静态模型 header；provider 未知或未配置返回 undefined；token 刷新失败 reject `ModelsError`（code "oauth"，存储的凭据保留可重试，重新登录可修复）；请求路径上的 reject 会转成流内 error 事件。

**语法点：方法重载**（:549-551）——同一个 `getAuth` 写了两个签名（收 string 或收 Model），再写一个宽类型的实现签名。TS 的重载只是"多个声明 + 一个实现"，没有 Java 那种真正的多个方法体。

### ③ `ModelsImpl`（:259-272 起）

`class ModelsImpl implements MutableModels`——接口的实现类。构造器（依赖注入的三连默认值）：

```ts
this.credentials = options?.credentials ?? new InMemoryCredentialStore();
this.modelsStore = options?.modelsStore ?? new InMemoryModelsStore();
this.authContext  = options?.authContext  ?? defaultAuthContext();
```

**语法点**：`options?.credentials` 可选链取字段，`?? ` 空值合并兜底——"传了用传的，没传用默认的"，一行完成。`new Map<string, Provider>()` 是哈希表（≈ Go `map[string]Provider` / Java `HashMap` / Python `dict`）。

### ④ `requireProvider`（:633-639）

4 行小函数：按 `model.provider` 查注册表，查不到 throw `ModelsError("provider", ...)`。这是本文件**少数会同步 throw 的地方**——但因为它只被 lazyStream 的异步 setup 调用，异常最终变成流内 error 事件（又回到"错误进流"哲学）。

### ⑤ `applyAuth`（:641-670）——认证解析流水线（核心私有方法）

干的事（配着代码读）：

1. `requireProvider(model)` 确认厂商存在；
2. `getAuth(model, ...)` 解析认证（就是你之前精读过的 `ApiKeyAuth.resolve` 那条链的入口）；解析不到 → throw `ModelsError("auth", "Provider is not configured: ...")`；
3. 逐字段合并，优先级（原文注释中译：*"显式传入的请求选项按字段优先；Models 专属的 transform 最后运行"*）：
   - `apiKey = options?.apiKey ?? auth.apiKey`（调用方显式传的 > 认证解析出的）
   - `headers = mergeHeaders(auth.headers, options?.headers)` 再过 `transformHeaders` 钩子
   - `env` 两边做对象展开合并；
4. 认证结果里的 `baseUrl` 能覆盖模型默认地址（`{ ...model, baseUrl: auth.baseUrl }`）；
5. 返回 `{ requestModel, requestOptions }`。

**两个精彩语法点**：

```ts
// a) 解构剔除：从 options 里拿走 transformHeaders（改名为 _ 表示弃用），剩余全部收进 providerOptions
const { transformHeaders: _transformHeaders, ...providerOptions } = options ?? {};

// b) Omit 类型运算：类型层面删除 transformHeaders 字段（与上面 a) 对应：值剔了，类型也要剔）
requestOptions: Omit<TOptions, "transformHeaders"> & ProviderRequestOptions;
```

解构 + 剩余（`...rest`）是 JS 的"不可变剔除"惯用法；`Omit<T, "k">` 是 TS 的类型级同款。两者配合 = "运行时和编译期一起拆包"。

### ⑥ `streamSimple`（:695-701）——调用主线

```ts
streamSimple(model, context, options): AssistantMessageEventStream {
    return lazyStream(model, async () => {
        const provider = this.requireProvider(model);
        const { requestModel, requestOptions } = await this.applyAuth(model, options);
        return provider.streamSimple(requestModel, context, requestOptions as SimpleStreamOptions);
    });
}
```

结构和你读过的 `lazy.ts` 完全同构：**同步返回空流，认证等异步准备在背后跑，失败变流内 error**。`as SimpleStreamOptions` 是类型断言——泛型 `TOptions` 编译期收窄后的宽窄转换，运行时无操作。`stream`（:672）同构，只是多一层泛型透传。

### ⑦ `complete` / `completeSimple`（:687 / :703）

```ts
async complete(model, context, options): Promise<AssistantMessage> {
    return this.stream(model, context, options).result();
}
```

一行：complete = stream 的 `.result()`。**没有单独的"非流式"实现**——非流式只是"流式但不监听中间事件"，还能顺便复用同一套重试/错误通道。设计上很经济。

### ⑧ `createModels`（:748-750）

工厂函数，`new ModelsImpl(options)`。存在理由：让调用方依赖 `MutableModels` **接口**而非具体类（依赖倒置，测试时可注入假实现）。

### ⑨ `createProvider`（:775-875）——从零件组装 provider

原文注释（中译）：

> 从零件构建一个 provider。内置 provider 工厂和 models.json 自定义 provider 都走这条路。单个 `api` 实现服务全部模型；`api` 映射则按 `model.api` 分发，没有对应条目的模型产生流错误。

三个看点：

1. **闭包做私有状态**：

```ts
let dynamicModels: readonly Model<TApi>[] = [];   // 普通局部变量
const currentModels = () => { /* 合并 baselineModels + dynamicModels */ };
```

`dynamicModels` 被内层函数（currentModels、refreshModels）持续读写——闭包让它成为**只有这些函数能访问的私有状态**，比类的 private 更彻底（连子类都看不见）。这是 JS/TS 替代"私有可变字段"的经典手法。
2. **目录合并**：动态模型按 `id` 覆盖基线里的同名项，没有的 push 追加（`findIndex` + 下标替换）。
3. **单实现 vs 映射**：`api` 参数既可以是单个 `ProviderStreams`（全部模型同协议），也可以是 `Record<TApi, ProviderStreams>` 映射（混合协议厂商）。:789 用 `typeof input.api.stream === "function"` 运行时探测是哪种。

### ⑩ `dispatch`（:794-805）

`apiFor(model)` 按 `model.api` 取协议实现；没有 → 返回一个"注定 error 的 lazyStream"（注意：不是同步 throw，还是错误进流）。这就是"按协议抽象"落到代码上的路由点——groq/deepseek/together 全都命中同一个 `openai-completions` 实现。

### ⑪ `calculateCost`（:891-911）——计价

算法：

1. `inputTokens = input + cacheRead + cacheWrite`（计价口径的"输入"含缓存读写）；
2. 分层计价（tiers）：输入量超过 `inputTokensAbove` 的最高一档适用**整个请求**（`matchedThreshold` 保证取最严格匹配档）；
3. 单价是"每百万 token 美元"，所以 `/ 1000000`；
4. 原文注释（中译）：*"Anthropic 对 1 小时缓存写入收 2 倍基础输入价"*——`cacheWrite` 拆成 `shortWrite`（原价）+ `longWrite`（2 倍）分别计。

**注意**：这个函数直接改传入的 `usage.cost` 字段（mutate 参数）——项目整体偏好不可变，这里是例外，读码时留意。

### ⑫ thinking 档位（:913-945）

- `getSupportedThinkingLevels`：从 `thinkingLevelMap` 算某模型支持的档位（`null` = 明确不支持；`xhigh`/`max` 必须显式映射才算支持）；
- `clampThinkingLevel`：请求的档位不支持时**就近取级**——先向高档找（i 递增），找不到再向低档找。为什么要"先上后下"：用户要"高思考"时给更高的仍符合意图，降低则偷工减料。

## 3. 进阶区速览（第一遍可跳过）

- **:325-451 refresh 机制**：`supersedeProviderRefresh`（换代 + abort 旧刷新）→ `publishProviderModels`（发布链 `publicationChains`：同 provider 的发布**串行排队**，避免乱序覆盖）→ `refresh()`（两阶段：先离线恢复缓存，再联网；`Promise.all` 并发各家）。`Provider & Required<Pick<Provider, "refreshModels">>` 这种类型 = "Provider 且 refreshModels 必有"（交叉类型 + Pick 挑字段 + Required 去可选）——类型体操先眼熟即可。
- **:570-620 login**：登录成功后写凭据存储那段有一串 `mutationStarted` / `Promise.race` 手工编排——处理"abort 信号到达时写库是否已开始"的竞态，保证已开始的写入不被误判失败。第一次读不必抠细节，知道"这段在和取消信号搏斗"即可。
- **:887 hasApi 类型守卫**：

```ts
export function hasApi<TApi extends Api>(model: Model<Api>, api: TApi): model is Model<TApi> {
    return model.api === api;
}
```

返回类型 `model is Model<TApi>` 叫**类型谓词**：函数返回 true 时，编译器把参数收窄成该类型。用法（原文注释中译）：动态查到的模型是宽类型 `Model<Api>`，`if (model && hasApi(model, "anthropic-messages"))` 之后 `model` 就是 `Model<"anthropic-messages">`，调用 stream 时选项全程有类型。≈ Go 的 `v, ok := x.(T)`，但作用于任意自定义判断。
